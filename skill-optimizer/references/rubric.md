# 评分规（Rubric）

每维度 0–10 分，按锚定描述就近取分，打分必须附原文证据。默认权重可在阶段 4 由用户调整。

## 维度与锚点

### D1 触发准确性（默认权重 25%）
- 0–3：description 含糊或过长堆砌，典型任务无法触发，或与其他 Skill 大面积撞车。
- 4–6：覆盖主要场景，但缺关键触发词，或存在明显误触发场景。
- 7–8：典型与近义触发语均覆盖，误触发场景基本排除，含具体文件类型/任务线索。
- 9–10：触发边界清晰（何时用、何时不用），单行 ≤1024 字符，与同类 Skill 可区分。

### D2 工作流完整性与逻辑（默认权重 25%）
- 0–3：步骤断裂、存在死分支或矛盾指令，照做无法完成任务。
- 4–6：主干可走通，但缺失败路径、前置条件或输出规范。
- 7–8：步骤闭环，分支有出口，失败有处理，输入输出明确。
- 9–10：通用流程可泛化到同类任务，特例被正确抽象，每步可验证。

### D3 Token 经济性（默认权重 15%）
- 0–3：正文冗长复述模型已知常识，大段内容应拆到 references 却未拆。
- 4–6：有冗余但尚可接受，渐进披露部分落实。
- 7–8：只写模型不知道的内容，正文 <500 行，大资料按需加载。
- 9–10：每段都经得起「删掉会怎样」的检验，示例替代解释，资源引用精准。

### D4 自由度匹配（默认权重 15%）
- 0–3：脆弱操作（格式转换、精确计算、外部 API）靠自由发挥，或开放决策被写死。
- 4–6：部分匹配，关键脆弱点无脚本或模板兜底。
- 7–8：脆弱操作低自由度（脚本/模板），开放决策高自由度（原则+示例）。
- 9–10：逐段匹配且说明理由，脚本输出对 LLM 友好、可确定性复现。

### D5 结构与规范合规（默认权重 10%）
- 0–3：frontmatter 缺失/格式错，命名不符，含多余文档文件。
- 4–6：基本合规但有瑕疵（description 多行、目录与 name 不一致、遗留 TODO）。
- 7–8：全部硬性检查通过。
- 9–10：全部通过且资源目录只含实际用到的部分，无空占位。

### D6 健壮性与边界（默认权重 10%）
- 0–3：无输入校验、无边界情况处理，异常输入直接崩溃或产出错误结果。
- 4–6：覆盖常见边界，少数极端情况未处理。
- 7–8：输入缺失/格式错/超大文件等常见边界有明确处理指引。
- 9–10：边界处理成体系，权限与外部依赖风险有交代，失败可恢复。

## 汇总

总分 = Σ(维度分 × 权重)。轮间同一维度分差 ≥2 时重评该维度并记录理由。逻辑问题清单中的「阻断级」问题（照做无法完成任务）无论总分多少都必须修复。
