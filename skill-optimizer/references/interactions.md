# 交互底座矩阵（24 点 × 5 簇）

本文件是 K10 交互治理的执行细则。每个交互点七属性：触发条件 / 问法与选项 / 未答默认（全自动行为）/ 风险档位 / 翻案方式。留痕统一：每次交互（问、答、代答、决策词汇、规格快照）写入 records 的 interactions-log.md。

## 通用规则（K10 展开）

- **决策词汇**：approve（采纳）/ edit（改了再采纳）/ reject（拒绝）/ skip（跳过走默认）/ 自由文本。宿主有结构化提问工具（如 AskUserQuestion）时对齐其格式：一次 1–4 题、每题 2–4 选项、推荐项首位标「推荐」、隐式自由文本。
- **风险三档**：必问（阻塞级：无目标、规格确认、删能力）/ 确认+diff（高危：替换触发词、结构大改、写目标外文件）/ 干+留痕（低危：可回滚的小决策）。
- **双节奏**：深挖期（知己簇）一次一问、开放式优先、卡住才给菜单；确认期（规格/交付簇）批量 ≤3 题、选项式、yes 即采纳推荐。
- **默认语义**：默认值必须说出口；代答留痕为「agent 决定（未确认）」，绝不记为「用户已同意」。
- **不重复问**：提问前查 interactions-log.md 与偏好台账，已答/可自查的不问。
- **拒绝缓冲**：被 reject 的方案记入拒绝清单，后续轮次不重复提议，除非前提变化。

## 个性化专属路径（知己体验总结）

1. 先查后问：Skill 原文能回答的绝不问用户（事实归 agent，决策归用户）。
2. 问→思→问→确认：每轮追问必须携带假设，复述确认后才动手。
3. 越用越懂：偏好台账携带全程，纠正沉淀须同意，翻案降权不追加。
4. 只动适配层：个性化改触发词/语言/默认值/profile，通用工作流与内核不动。
5. 透明可翻案：每个代答说出口、留痕、可逐条翻案——用户永远有最后决定权。
