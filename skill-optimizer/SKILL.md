# Skill Optimizer

微内核架构：**内核是确定性的工程学规则，大模型是可插拔的能力层**。内核不信任任何未经校验的模型输出；模型不直接接触文件——一切写入必须穿过内核闸门。主观环节负责创造，客观环节负责兜底，契约负责传递，追溯负责问责，备份负责后悔，记录负责复盘。成品交付后不复测。

## 内核（确定性层，全程生效，不可被能力层推翻）

**K1 契约闸门**：每阶段有明确产出物，进入下一阶段前校验完整性，缺项即停并报告，不带病推进。

**K2 客观硬检查**：只有过/不过——frontmatter 以 --- 成对包裹、name 为 hyphen-case 且与目录同名、description 单行 ≤1024 字符、正文 <500 行、无多余文件、无未解决 TODO、资源引用路径真实存在。豁免：`*-backup-*` 备份文件与同级 records 目录不计为多余文件（自优化场景必需）。交付前必须全过。

**K3 双向追溯**：《优化规格》是唯一事实源。每处改动对应规格某一条；规格每条落到某处改动或标注「明确放弃+理由」。对不上即交付失败。

**K4 备份闸门**：覆盖原文件前必须先备份为 `<原名>-backup-<日期>`（同目录）。备份失败则重写阶段中止。原备份永不修改。

**K5 确认闸门**：写任何目标文件前，须有用户对《优化规格》的确认（I-17，确认绑定规格快照，快照变更则确认失效），**或用户事先明确的全自动授权**。授权识别：「全自动」「别问我」及委托式指令（「给我搞好」「直接做」等明确委托且无保留条件）均视为事先授权；存疑时经 I-02 确认一次。全自动授权不豁免留痕：每个默认决策逐条记录并在报告列出。评审通过不等于改写授权。

**K6 全程留痕**：在目标 Skill 同级创建 `skill-optimizer-records/<名称>-<日期>/`，落盘 9 文件：opinion.md（用户意见）、detect.md（拆解与逻辑问题）、review-log.md（多评委审核记录）、research.md（四源调研）、ideas.md（发散与借鉴）、spec.md（优化规格）、loop-log.md（全部循环轮次）、interactions-log.md（交互台账：每问/答/代答/决策词汇/规格快照）、report.md（交付报告）。每阶段产出即写盘，审核记录含评委身份、轮次、评分、证据、异议与裁决。

**K7 失效降级表（FMEA）**：

| 失效模式 | 检测 | 降级路径 |
| --- | --- | --- |
| 联网调研失败/无结果 | 搜索返回空或报错 | 用 references/research.md 内置快照，标注「调研降级」 |
| 用户中途不回复 | 交互模式规格未确认 | 不写目标文件，记录保留待续；全自动模式按默认决策规则推进 |
| 重写产物违反 K2 | 硬检查不过 | 自动修正重查；两次仍不过则交付失败 |
| 追溯核对缺口 | K3 不过 | 补齐改动或放弃理由，重核 |
| 目标读取不全 | 文件缺失/超大 | 只评可读部分，标注覆盖范围 |
| 个性化破坏核心能力 | 对照原能力清单 | 回退该条改动，保留其余 |
| 记录写盘失败 | 目录/权限错误 | 修复后重写；不可修复则中止并报告 |
| 跨模型评委不可用 | 无第二模型/子代理 | 三视角独立打分+证据强制，标注「未跨模型校准」 |

**K8 权限边界**：只读公开资料，不执行来路不明的脚本；不删除用户未同意删除的能力；拿不准的保留并标注。第三方 Skill 提示来源可信度与审计状态（社区普查显示大多数 skill 未经审计）。

**K9 循环治理**：一切循环共用同一治理规则——轮次上限（默认 3）、停滞退出（连续 2 轮无改进即停）、分数下降必回滚本轮、每轮写入 loop-log.md。外循环回注必须携带「回注理由 + 影响范围」，只重跑受影响部分，禁止无差别从头再来。

**K10 交互治理**：一切交互受 [references/interactions.md](references/interactions.md) 的 24 点矩阵约束——
1. **Horvitz 闸门**：期望收益 > 打断成本才问；阻塞项必问，低危项直接干+留痕，不反复问「要继续吗」。
2. **问题预算**：确认期每轮批量 ≤3 题；深挖期一次一问；提问前查交互台账，已答/可自查的不重复问。
3. **先查后问**：事实归 agent 自查，决策才归用户；Skill 原文能回答的绝不问用户。
4. **选项+推荐**：选项式提问、推荐项首位标「推荐」、yes 即采纳推荐；挑选/裁决给 ≥3 选项允许平局。
5. **默认说出口**：代答必须明示，留痕为「agent 决定（未确认）」而非「用户已同意」。
6. **环节边界检查点**：只在阶段边界发问，不打断执行流。
7. **统一决策词汇**：approve / edit / reject / skip / 自由文本；被拒方案入拒绝缓冲，不重复提议。
8. **思考后追问**：追问必须携带假设（先消化再问），禁止不经思考连环发问。
9. **全程留痕**：每次交互写入 interactions-log.md。
10. **风险三档**：必问（阻塞级）/ 确认+diff（高危）/ 干+留痕（低危可回滚）。

## 循环系统（内嵌内循环 + 跨环节外循环）

**循环原语**（可在任意环节实例化）：执行 → 测量 → 与上轮对比 → 改进则保留继续 / 无改进记停滞 / 变差则回滚本轮 → 退出判定（收敛 | 停滞达限 | 轮次达限，K9）→ 记录本轮。

**内循环（环节内收敛）**：

| 环节 | 循环体 | 退出条件 |
| --- | --- | --- |
| 阶段 2 检测 | 拆解→查验→发现新问题→补拆解 | 无新增问题或 3 轮 |
| 阶段 3 评审 | 多评委打分→分歧重评→再比 | 分歧 <2 分或 3 轮 |
| 阶段 4 调研 | 四源检索→覆盖缺口检查→补搜 | 四源均有有效来源或 3 轮（深度档不设保守搜索上限） |
| 阶段 5 发散 | 出创意→可行性自检（能否落回改动）→淘汰/补充 | 全部有落点或明确放弃，≤2 轮 |
| 阶段 6 重写 | 重写→K2/K3→修正重查 | 全过或 2 次失败交付终止 |

**外循环（跨环节回注，任一环节可触发）**：
- **评审→检测**：评委发现未入册逻辑问题 → 回阶段 2 入册 → 重评受影响步骤
- **调研→检测**：调研推翻 Skill 前提（方法过时/依赖失效）→ 回阶段 2 重检受影响层
- **发散→评审**：采纳的创意改变评估基准 → 对受影响维度重评分
- **意见→任意环节**：用户中途注入新意见（I-19）→ 更新 opinion.md → 列影响范围 → 增量重跑受影响环节
- **交付→翻案**：用户对某决策翻案（I-21）→ 凭备份回滚该条 → 重跑阶段 6（用户驱动，不违反「不复测」——不复测指不自行发起验证循环）；翻案使旧偏好降权而非追加

循环不是兜圈：每轮必须产生可测量的增量（新问题入册/分差收窄/来源补齐/创意落点），无增量的轮次按 K9 停滞处理。

## 交互底座（24 点 × 5 簇）

完整矩阵见 [references/interactions.md](references/interactions.md)：**开场 4 点**（目标/执行模式/优化模式/调研强度）、**知己 6 点**（首问/假设追问/复述确认/硬约束/权重/偏好 profile）、**检测评审 3 点**（入册裁决/争议裁决/校准）、**调研发散 3 点**（缺口补充/创意挑选/借鉴冲突）、**规格交付 8 点**（规格确认/高危单确/中途注入/交付格式/翻案/偏好沉淀/触发自检/第三方来源）。每点七属性：触发/问法选项/未答默认/档位/翻案，留痕统一进 interactions-log.md。

**知己四拍**（个性化采集的核心节奏）：首问（开放 2–3 题）→ 消化思考（对照原文与检测形成假设，此间不发问）→ 假设追问（验证而非索取）→ 复述确认（playback，确认后才动手）。个性化只动适配层（触发词/语言/默认值/profile），通用工作流与内核不动。

## 能力层（按内核契约依序执行）

**执行模式三档**：全自动（明确授权或委托式指令，K5）/ **智能（默认）**：只问阻塞项+高价值项，其余按各交互点默认决策推进并留痕 / 全交互（每个交互点等用户）。各点未答默认见交互矩阵「未答默认」列；自动决策一律保守（拿不准就保留原样并标注），逐条记入 spec.md，报告附自动决策清单，用户事后可逐条翻案。

### 阶段 1：知己式意见采集 → opinion.md

目标 Skill 路径未提供先询问（I-01）。按四拍递进（I-05→消化→I-06→I-07），不做问卷盘问；全自动模式只收集用户主动给出的信息，其余走默认：
- 执行模式与优化模式（I-02/I-03）：质量优化 / 个性化优化（「用着不顺手」即个性化）/ 兼有
- 痛点与期望：哪里别扭、想改成什么样、最近一次不顺手的实例
- 不可妥协项（I-08）：触发语、语言格式、默认值、行数限制、本地环境约束
- 权重表态（I-09，只问高熵维度）与偏好 profile（I-10，个性化时）

意见整理成 opinion.md，作为后续所有检测与评审的**第一输入**。第三方 Skill 记录来源（I-24，未知标「来源不明」）。

### 阶段 2：全量检测 → detect.md

以「用户意见 + Skill 本身的全部逻辑与流程」为双重基准：
- **六层拆解**：触发层、工作流层（步骤序列+输入输出+分支+失败路径）、自由度层、资源层、泛化层、适配层（意见逐条对照现状列适配缺口，每条标「改哪里怎么改」）。
- **逻辑查验**：逐步骤查矛盾、死分支、缺失前置条件、循环无出口、指令与资源不一致、触发描述与正文能力不符。每个问题给位置、影响、修复方向，按严重度排序，编号入册——**阶段 6 必须全部清零或给出明确不修理由**。
- 用户意见指出的问题即使检测未复现，也入册待评委裁决（I-11）。

### 阶段 3：多评委审核（每步留痕）→ review-log.md + 评分卡

对拆解出的**每个步骤/环节**逐一过多评委，不只评整体：
- 评委席：至少 3 个独立视角——逻辑评委（可执行性）、体验评委（触发与顺手程度，以用户意见为据）、工程评委（token 经济、自由度、规范，按 [references/rubric.md](references/rubric.md) 锚定评分）。跨模型评委启用条件：存在可用的第二模型或独立子代理；不满足按 K7 降级并标注。校准选项见 I-13。
- 每评委独立打分 0–10 并附原文证据；分歧 ≥2 分的项重评并记录裁决理由，重评仍分歧交用户裁决（I-12）。警惕长度偏差与自偏好。
- **全程记录**：每步的评委身份、轮次、分数、证据、异议、裁决写入 review-log.md。客观硬检查（K2）结果直接计入工程评委的 D5。
- 产出：分步评分卡 + 汇总总分 + 阻断级问题标记。

### 阶段 4：四源自动调研与整合 → research.md

自动 WebSearch 四类来源，无需用户触发；**可与阶段 2/3 并行或前置**（交互设计类优化应以调研为输入）。强度三档（I-04）：精简（纯个性化：只查该 Skill 最新版本与社区已知问题）/ 标准 / 深度（并行多路代理、不设保守搜索上限，仍受 K9 治理）：
1. **GitHub 高分作品**：同领域热门仓库与最佳实践（`<领域> skill/prompt/agent best practices github stars`）
2. **最新论文期刊**：相关方法学（`<领域> arxiv 2025 2026`）
3. **最新研究新闻**：领域与平台近期进展
4. **社区论坛**：真实用户反馈与踩坑（Reddit、Hacker News、V2EX、掘金、天池论坛等，搜 `<skill名/领域> 问题 经验 论坛`）

整合成简报：每条注明来源链接、可借鉴点、与目标 Skill 的关联，标注建议采纳/可选/不适用。四源结论冲突时并列呈现（I-16）。失败按 K7 降级。

### 阶段 5：思维发散与借鉴 → ideas.md

基于整合简报做受控发散：产出 3–6 条升级创意（新维度、新交互、新隐喻、跨领域移植），每条带灵感来源（指向 research.md 条目）、收益、成本、采纳建议，且必须能落回具体改动或明确放弃理由。挑选见 I-15。借鉴映射表：每条采纳的借鉴 → 对应改动位置 → 解决的检测问题编号。

### 阶段 6：优化规格确认 → 全自动优化，逻辑问题清零 → 成品 + report.md

1. 向用户展示：评分卡、逻辑问题清单、调研简报、创意清单、拟定的《优化规格》（目标、权重、硬约束、采纳的调研点与创意、意见落实映射）。交互模式：争议点逐条裁决，用户确认（I-17，绑定规格快照）后落盘 spec.md（K5）；全自动模式：按默认决策规则生成规格，自动决策逐条标注后落盘 spec.md，直接执行（K5 事先授权）。
2. 全自动重写，不逐轮打断：K4 备份 → 修复**全部**逻辑问题（清零或书面不修理由）、按权重改进低分维度、落实采纳的调研与创意、逐条落实用户意见与适配缺口、保持硬约束。个性化不破坏核心能力、只动适配层；触发词按用户习惯扩充而非替换；删能力/替换触发词/结构大改逐项确认（I-18）。
3. K2 硬检查 + K3 双向追溯，不过按 K7 处理。
4. 交付成品 + report.md，末尾必须附**全量交付清单**，四项齐全：
   - **所有改动**：逐文件列出每处修改的原文 → 新文对照（含删除与新增），每处挂规格编号与问题编号
   - **所有优化**：每条优化项的动机、依据（评分维度/调研来源/用户意见）、预期效果
   - **所有建议**：采纳的与未采纳的全部列出——未采纳项（含落选创意、评委异议、检测发现但决定不修的问题）逐条给理由；另附后续可选建议
   - **所有变化**：前后评分卡对比、结构变化（文件/章节增删）、行为变化（用户实际使用时会感受到的不同）、逻辑清零核对表、**前后 token 估算**（防过拟合警示：不宣称未验证的收益）
   另附：**未改清单**（明确保留未动的部分）、自动决策清单（全自动模式：每个代答的交互点、所用默认规则、理由、事后翻案方式）、**触发正负例与手动调用说明**（I-23，供用户自行验证，不自行跑测试）、调研来源与备份位置；第三方 Skill 附来源与改动摘要便于上游合并。清单缺任何一项即交付不完整，按 K1 补齐。
5. 任务结束询问偏好沉淀（I-22，未经同意不写）。**不复测**。告知重启会话或 `/skills reload` 生效。

## 体验原则

向用户展示内核在工作：每阶段亮出产出物与闸门状态（过了什么、拦了什么、降级了什么），审核记录与逻辑清零表随时可查。可靠与透明本身就是颠覆性体验——用户看到的不是聊天机器人，是一台精密机器。

知己感是另一重体验：先查后问、问前有思、复述确认、偏好记住不重复问、每个代答说出口且可翻案——用户感到被深度理解，且永远握有最后决定权。
